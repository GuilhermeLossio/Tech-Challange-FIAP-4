# Update Note - 2026-04-27

## Topic
Monthly forecast batch generation and Athena catalog provisioning for S3-published datasets.

## Status
Completed.

## Executive Summary
Two serving-oriented capabilities were added to the project. First, the pipeline can now materialize a 30-business-day recursive forecast dataset in parquet format under the processed zone. Second, the repository now includes a scripted Athena catalog provisioner that creates the database and external tables needed to query the raw, refined, feature, and forecast zones directly from S3.

## Context
The project already had historical ingestion, refined dataset generation, feature engineering, and model training. What was still missing for practical consumption was a serving-friendly output and a repeatable way to expose S3 data through Athena without manually writing DDL every time.

## Recorded Decisions

### 1. Keep forecast output in a dedicated serving zone

The monthly forecast dataset is stored separately from `raw`, `refined`, and `feature` data:

- `raw` remains the historical ingestion zone
- `refined` remains the sliding-window training zone
- `feature` remains the engineered-feature training zone
- `forecast_data` becomes the serving zone for downstream analytics and future APIs

### 2. Use flat parquet rows for forecast serving

Each forecast row represents one symbol on one future business day. This avoids nested payloads and keeps the schema easy to query from Athena.

### 3. Provision Athena from code, not ad hoc SQL

Athena DDL is now generated by a CLI and use case, aligned with the same S3 bucket and prefix configuration already used by the data pipeline.

## Data Layout Introduced

### Forecast serving dataset

```text
data/processed/
└── forecast_data/source=yfinance/symbol=NVDA/lookback=60/horizon_days=30/extraction_date=2026-04-22/generated_at=20260427T004459Z/forecast.parquet
```

S3 equivalent:

```text
s3://<processed-bucket>/<processed-prefix>/forecast_data/source=yfinance/symbol=NVDA/lookback=60/horizon_days=30/extraction_date=2026-04-22/generated_at=20260427T004459Z/forecast.parquet
```

### Athena catalog objects

The Athena provisioner creates:

- `raw_ohlcv`
- `refined_close_lkb60`
- `feature_close_lkb60`
- `forecast_close`

## Operational Notes

- The forecast generator is recursive. It rolls a D+1 model forward for 30 future business days.
- The forecast horizon always starts after the last date present in the raw zone.
- With the current default raw ingestion behavior, that last date is the final day of the last completed fiscal year unless `--end-date` is explicitly overridden.
- Athena `refined_*` and `feature_*` table schemas depend on `lookback`, because the lag columns are physically materialized in parquet.

## Example Commands

### Generate forecast dataset

```bash
python scripts/generate_forecast.py --extraction-date 2026-04-22 --symbols NVDA AMD TSM ASML QCOM --horizon-days 30
```

### Preview Athena DDL

```bash
python scripts/provision_athena.py --print-only --lookback 60
```

### Execute Athena provisioning

```bash
python scripts/provision_athena.py --lookback 60 --output-s3-uri s3://your-athena-results-bucket/path/
```

## Rationale

- The separation of training and serving zones preserves historical lineage and keeps the training datasets immutable.
- Flat parquet output reduces friction for Athena, Glue, and future API consumers.
- Scripted Athena provisioning removes manual setup steps and makes the catalog reproducible across environments.
- Reusing the existing environment variables keeps the new capabilities consistent with the rest of the project.
