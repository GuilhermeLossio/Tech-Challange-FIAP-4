# Update Note - 2026-05-17

## Topic
IBM Quantum runtime guard and enriched comparison report for article-ready benchmarking.

## Status
Implemented.

## Executive Summary
The project now protects real IBM Quantum runs with an explicit confirmation flag and enriches the model comparison report with execution environment, cost-profile, hardware-observability, and article-comparison sections.

## Context
The benchmark compares a production-oriented Keras LSTM against a Qiskit VQC. Running the VQC in simulator mode is safe and repeatable, but running it in cloud mode can submit jobs to physical IBM Quantum hardware and consume runtime minutes. The report also needs to support an academic article by distinguishing simulator results from real NISQ hardware behavior.

## Recorded Decision
Require `--confirm-ibm-runtime-cost` before any cloud command that can submit an IBM Quantum job.

The guard applies to:

- `scripts/train_and_compare_models.py --quantum-mode cloud`
- `scripts/train_model_quantum.py --mode cloud`
- `scripts/test_ibm_quantum.py --mode cloud`

Backend listing remains allowed without confirmation because it does not submit a QPU job.

## Implementation Summary
The scripts now perform a fast `sys.argv` preflight before heavy imports. If cloud mode is requested without the confirmation flag, execution stops immediately before TensorFlow, Qiskit, matplotlib, or IBM Runtime setup can proceed.

The comparison report generated by `scripts/train_and_compare_models.py` now includes:

- execution environment and cost profile
- backend and execution mode
- shots, optimizer, max iterations, qubits, and sampled split sizes
- function evaluations and objective value when available
- distinction between simulator/fake backend and IBM real hardware
- IBM real-hardware variables for the article: queue time, execution time, wall-clock time, gate errors, readout error, T1/T2, and mitigation
- IBM observability checklist for future `job.metrics()` and `job.result().metadata` capture
- QPU-second cost-model note
- article-ready comparison table between Keras LSTM and Qiskit / IBM real hardware
- recommendation to repeat real-hardware experiments 3-5 times and report mean plus standard deviation

## Methodology Note
The current VQC abstraction captures useful optimizer and backend metadata, but it does not yet expose all low-level IBM Runtime job metrics. For publication-grade hardware experiments, a future lower-level runner should persist:

- `job.metrics()`
- `job.result().metadata`
- QPU seconds
- queue time
- transpiled circuit depth
- two-qubit gate count
- bitstring histograms
- expectation values
- mitigation configuration
- repeated-run variance
